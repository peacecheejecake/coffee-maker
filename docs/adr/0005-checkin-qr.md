# 0005. 출두 QR

- 상태: 채택 (2026-11-20)
- 관련: ADR 0003, DESIGN.md §2.8

## 맥락

출두 구역(ADR 0003)은 건물 단위까지만 가린다. 같은 건물 1층 카페에서 미리 출두 체크하는 것을 막아 달라는 요청이 있었다. 검토한 방법은 다음과 같다.

- **고도**: 브라우저 `coords.altitude`는 실내에서 오차가 10–30m이고, Android Chrome은 값을 주지 않는 경우가 많다. 2–3층 차이(4–7m)는 구분할 수 없다. 기압계는 네이티브 전용이고, 날씨에 따라 기준점을 다시 맞춰야 한다.
- **NFC 태그**: iPhone 웹에서는 직접 읽을 수 없다. 태그에 링크를 넣으면 웹에서도 열리지만, 사람마다 기기 지원과 설정이 다르다.
- **사무실 Wi-Fi(BSSID)**: 네이티브 전용이다. iOS는 별도 권한(entitlement)이 필요하다.
- **QR**: 웹과 네이티브 모두 카메라로 읽을 수 있고, 층마다 붙일 수 있다. 출력해 붙이기만 하면 된다.

## 결정

- `Ruleset.checkInQr?: { codeHash }`. 없으면 지금과 같다. 첫 확정이나 `ruleset` 발의로만 바뀐다. 서버 스키마는 바뀌지 않는다.
- **코드와 해시**: 코드는 혼동 문자를 뺀 32자 알파벳 20자(100비트)다. 규정에는 `SHA-256("coffee-maker/checkin/" + code)`만 남긴다.
  - 해시만 남기므로 앱 화면에서 QR을 다시 띄울 수 없다. 발급 직후 그 화면에서만 저장할 수 있고, 잃어버리면 새로 발급한다.
  - SHA-256은 core 안에 동기 구현했다. `decide`가 동기 함수이고, core에는 WebCrypto 타입이 없다.
- **QR 내용**: `https://<공개 주소>/?checkin=<code>`. 앱 안 스캐너는 어느 주소의 링크든, 코드만 들어 있든 읽는다. 휴대폰 기본 카메라로 찍으면 웹앱이 열리고, 장부가 동기화되면 그 코드로 체크한 뒤 주소에서 코드를 지운다.
  - 네이티브 셸에서 발급하면 셸 자체 주소(`capacitor://localhost` 등)는 카메라 앱이 열 수 없으므로 공개 웹 주소를 쓴다.
  - iOS 홈 화면 PWA는 Safari와 저장소가 분리되어 있어서, 카메라 앱으로 연 링크는 Safari에서 열린다. 이 경우에는 앱 안의 [QR 찍고 출두]를 쓴다.
- **판정**: `CheckIn { position?, qrCode? }`. 규정에 QR이 있으면 `decide`가 해시를 비교한다. 없으면 `QrRequired`, 다르면 `QrMismatch`를 낸다. 출두 구역과는 독립적이며 둘 다 통과해야 한다. 코드는 이벤트에 넣지 않는다.
- **자동 출두 체크**: QR을 쓰는 동안에는 동작하지 않고, 설정도 숨긴다.
- **스캐너**: `getUserMedia`(후면 카메라)로 받은 프레임을 480px 폭으로 줄여 jsQR로 150ms마다 읽는다. jsQR(약 45 kB)과 생성기 qrcode-generator(약 20 kB)는 해당 화면을 열 때만 불러온다. iOS Safari에는 `BarcodeDetector`가 없어서 jsQR을 쓴다.
- **권한**: 네이티브 셸에는 카메라 권한이 이미 있다(상환 증빙). iOS 사용 설명에 출두 QR을 추가했다.

## 결과

- (+) 웹·iOS·Android에서 같은 코드로 동작하고, 층을 확실하게 구분한다.
- (−) QR 사진을 찍어 두면 어디서나 찍을 수 있다. 위치와 마찬가지로 정직하게 쓰도록 돕는 장치이며 증명이 아니다. 더 막아야 하면 주기적으로 새로 발급(발의)하거나, 화면에 바뀌는 코드를 띄우는 방식(서버 서명 필요)을 검토한다.
