# 0002. 모드, 자진 출두(출석) 모드, 발의·투표, 일정

- 상태: 채택 (2026-10-24)
- 관련: ADR 0001, DESIGN.md §2.3, §2.6, §5.3

## 맥락

지금까지의 장부는 "누군가 다른 사람의 지각을 기록하는" 공유 방식 하나뿐이다. 요청된 변경은 다음과 같다.

- 방장이 그룹 모드를 바꿀 수 있고, 방장을 다른 사람에게 넘길 수 있다.
- 새 모드에서는 각자 직접 출석체크를 하고, 체크하지 않은 평일에는 업보가 자동으로 쌓인다.
- 공통 규칙은 처음에 명시적으로 확정하고, 그다음부터는 발의와 투표로만 바꾼다.
- 상환은 동의를 받아 한 잔씩 한다. 다른 사람의 커피는 n−2명, 내 커피는 n−1명의 동의가 필요하다.
- 시간과 무관하게 업보를 수동으로 고칠 수 있어야 하며(발의 후 투표), 공휴일·휴가를 사후에도 등록할 수 있어야 한다.

## 결정

### 모드

- `GroupMode = 'shared' | 'attendance'`이다. 화면 이름은 각각 "공동 장부"와 "자진 출두"다.
  새 그룹은 생성할 때 `ModeChanged { mode: 'attendance' }`를 함께 발행해 자진 출두가 기본값이 된다.
  `ModeChanged`가 없는 기존 그룹은 `shared`로 해석한다.
- `ModeChanged { mode }`는 방장만 발행할 수 있다(서버에서도 검사). 모드를 바꾸면 자진 출두 규칙 확정 상태가 초기화된다.
- `OwnerTransferred { to }`는 방장만 발행할 수 있다. 서버는 같은 트랜잭션에서 `members.role`을 옮기며, 계정에 연결되지 않은 플레이어에게는 넘길 수 없다.

### 자진 출두 모드

- **규칙 확정:** `RulesAdopted { ruleset }`는 방장이 명시적으로 클릭해 발행한다. 출석 판정은 확정한 날의 **다음 날**부터다.
  이후 `RulesetChanged`는 무시되고, 규칙 변경은 발의(`ruleset`)로만 한다.
- **출석:** `CheckedIn { workDate }`는 본인만 발행한다. 출석 시각은 이벤트의 `serverAt ?? at`을 그룹 시간대로 환산해 `evolve`에서 정한다.
  클라이언트가 시각을 정하지 않는다. 그 시각의 날짜가 `workDate`와 다르면 무시한다. 늦었으면 기존 규칙(유예, 고정 또는 구간별 잔 수)대로 기록한다(`origin: 'checkIn'`).
  자진 출두 모드에서는 개인별 출근 시각 예외를 쓰지 않는다. 모두 공통 규칙을 따른다.
- **미출석:** `AttendanceMissed { playerId, workDate }`는 아무 멤버의 클라이언트나 지나간 날을 정산하면서 발행한다.
  id가 `miss:<group>:<player>:<date>`로 결정적이라 중복 발행은 서버에서 멱등 처리된다.
  `evolve`는 다음을 모두 다시 검증하고, 하나라도 어긋나면 무시한다.
  - 모드가 자진 출두이고, 출석 판정 시작일 이후다.
  - 플레이어가 그 전날까지 가입해 있었다.
  - 평일이고, 공휴일·휴가가 아니다.
  - 그날 출석이나 미출석 기록이 아직 없다.
  - 발행 시각이 그 날짜가 끝난 뒤다.
  잔 수는 규칙상 최대치다(고정 잔 수, 또는 구간별 규칙의 마지막 구간). `origin: 'missed'`로 기록한다.
- **입장 즉시 플레이어 등록:** 초대로 들어오면 기존 플레이어를 고르는 단계 없이 바로 자기 플레이어를 만든다.
- 다른 사람의 지각 기록(`RecordArrival`)과 즉시 상환(`Redeem`)은 이 모드에서 막는다.

### 일정

- `HolidaySet { date, name, off }`: 그룹 공휴일이다. `off: false`는 공휴일 해제다(예: 근무하는 법정 공휴일).
  자진 출두 모드에서는 공통 규칙에 속하므로 발의로만 바꾸고, 공동 장부 모드에서는 누구나 바로 등록한다.
- `VacationSet { date, on }`: 본인 휴가이며 사후 등록도 가능하다.
- 법정 공휴일은 core에 연도별 데이터로 내장한다. 규칙의 `publicHolidays: 'KR' | 'none'`(기본 `KR`)으로 켜고 끈다. 데이터는 매년 갱신이 필요하다.
- 공휴일이나 휴가가 사후에 등록되면, 그날의 출석·미출석 기록은 `excused`로 닫는다. 이미 상환한 잔은 기존 원칙대로 `overpaid`로 남긴다.

### 발의·투표(Motion)

- 탕감과 별개인 범용 발의다: `MotionProposed { motion, voters, expiresAt }`, `MotionVoted`, `MotionWithdrawn`.
- 가결은 투표자 전원 찬성이고, 한 명이라도 반대하면 부결이다. 기한은 규칙의 `waivePolicy.ttlHours`를 쓴다.
  발의자가 투표자에 포함되면 찬성표가 자동으로 들어간다. 투표자가 0명이면 발의 즉시 가결이다.

| 종류 | 모드 | 투표자 |
|---|---|---|
| `ruleset` | 자진 출두 | 전원 |
| `holiday` | 자진 출두 | 전원 |
| `adjust` (±잔, 사유) | 모두 | 대상자 제외 전원 |
| `redeem` (1잔) | 자진 출두 | 발의자·채무자 제외 전원. 즉 남의 커피는 n−2명, 내 커피는 n−1명이다. 2인 그룹에서 남의 커피는 즉시 가결된다. |

- **가결 시 효과:**
  - `ruleset`은 가결일부터 적용된다.
  - `adjust`의 +는 `origin: 'adjustment'` 기록으로 잔을 발급한다. −는 탑 맨 위 잔부터 지우고 해당 기록의 잔 수를 줄인다.
  - `redeem`은 한 잔을 상환 처리한다.
- 서버는 `WaiveVoted`와 같은 방식으로 투표자 여부, 기한, 1인 1표를 검사한다.

## 결과

- (+) 모든 변경이 이벤트로 남는다는 ADR 0001의 원칙을 유지한다. 자동 적립도 이벤트이므로 상환, 되돌리기, 통계가 기존 경로를 그대로 쓴다.
- (−) 아무도 앱을 열지 않으면 미출석 적립이 늦게 기록된다. 날짜 기준으로 정산하므로 결과는 같다.
- (−) 법정 공휴일 데이터를 매년 갱신해야 한다.
- (−) 동의로 처리한 상환은 10분 되돌리기 대상이 아니다.
