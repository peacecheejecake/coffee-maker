# 0003. 출두 구역(위치 기반 출두 체크)

- 상태: 채택 (2026-11-02)
- 관련: ADR 0002, DESIGN.md §2.7

## 맥락

자진 출두 모드에서 "회사 근처에 오면 자동으로 출두 체크"가 요청되었다. 어렵다면 도착 알림("도착했어요 — 체크할까요?"), 그것도 어렵다면 최소한 구역 안에서만 체크되게 해 달라는 것이다.

제약은 다음과 같다.

- 웹앱(PWA)은 앱이 닫혀 있거나 백그라운드에 있을 때 위치를 받을 수 없다. 브라우저에는 지오펜싱 API가 없다.
- 위치는 기기가 보고하는 값이다. 브라우저 개발자 도구나 위치 조작 앱으로 바꿀 수 있고, 서버는 이를 검증할 수 없다.
- 개인별 위치 이력을 서버에 남기고 싶지 않다.

## 결정

### 구역은 규정의 일부다

- `Ruleset.workplace?: { lat, lng, radiusMeters (50–1000 정수), label? (≤40자) }`. 없으면 지금처럼 어디서나 체크할 수 있다. 기존 규정과 이벤트는 그대로 유효하다.
- 첫 확정(`RulesAdopted`)과 규정 발의(`ruleset` motion)를 그대로 쓴다. 구역만을 위한 이벤트는 새로 만들지 않는다. 그래서 서버 스키마도 바뀌지 않는다(규정은 jsonb로 저장되고, 서버는 시간대만 읽는다).
- 공동 장부 모드에는 출두 체크가 없으므로 구역 설정도 보이지 않는다.

### 체크는 구역 안에서만 한다(클라이언트에서 판정)

- `CheckIn { position?: GeoFix }` 명령에 위치를 함께 넘기면, `decide`가 그날 규정의 구역과 비교한다. 결과는 `LocationRequired`, `OutsideWorkplace`, `LocationUncertain` 가운데 하나이거나 통과다.
- **발행되는 `CheckedIn` 이벤트에는 위치가 들어가지 않는다.** 위치는 확인에만 쓰고 버린다. 스토어도 마지막 위치를 보관하지 않는다(UI에 보일 거리·정확도 상태만 메모리에 둔다).
- `evolve`와 서버는 위치를 다시 검증하지 않는다(검증할 데이터가 없다). 수정한 클라이언트는 구역을 무시할 수 있다. 이 점은 숨기지 않고 DESIGN.md §2.7에 적었다.
- 오차: `거리 − 정확도 ≤ 반경`이면 안으로 본다. 정확도가 `max(반경, 100m)`보다 나쁘면 판단하지 않는다(`uncertain`). 실내 GPS가 수십 m 흔들려도 자리에 앉은 사람이 막히지 않고, IP 기반 추정(±수 km)으로는 체크할 수 없다.

### 포그라운드 자동 체크

- 기기별 설정(`autoCheckIn:<group>`, 기본 꺼짐)이다. 켤 때 위치를 한 번 읽어 권한 요청을 띄운다. 거부하면 꺼진 채로 남는다.
- 앱을 열거나 앞으로 가져올 때, 그리고 열려 있는 동안 2분마다 위치를 읽는다. 구역 안이면 그 위치로 바로 체크하고 토스트를 띄운다. 오늘 체크할 일이 없으면(이미 체크함, 휴일, 판정 전) 위치를 읽지 않는다.
- 미출두 정산처럼, 장부가 동기화된 상태(`local`/`synced`)에서만 시도한다. 같은 계정의 다른 기기에서 이미 체크했는데 그 사실을 모르는 기기가 중복 체크를 보내지 않게 하기 위해서다.
- 지각 판정은 그대로 이벤트의 서버 시각이다.

### 포트와 어댑터

- `GeolocationPort { supported(); current(): Promise<LocateResult> }`(packages/app). 웹과 네이티브 셸 모두 브라우저 Geolocation API 어댑터(`createBrowserGeolocation`, packages/adapters)를 쓴다. 테스트는 `createFakeGeolocation`을 쓴다.
- 네이티브 셸은 포그라운드 권한만 선언한다. iOS는 `NSLocationWhenInUseUsageDescription`, Android는 `ACCESS_COARSE_LOCATION`·`ACCESS_FINE_LOCATION`이다. 웹뷰의 geolocation은 Capacitor 브리지가 OS 권한으로 연결한다.

### 지도

- Leaflet 1.9 + OpenStreetMap 타일이다. 구역 설정 화면에서만 지연 로딩한다(JS 약 44 kB, CSS 약 6.5 kB, gzip 기준). 지도를 불러오지 못해도 현재 위치와 검색으로 고를 수 있다.
- 장소 검색은 Nominatim이다. 제출할 때만 검색한다. 입력 중 자동완성은 사용 정책상 금지다.
- OSM 공개 타일 서버의 사용 정책은 "가벼운 사용, 출처 표시"다. 이 화면은 규정을 정할 때만 쓰므로 이 정책에 맞는다. 사용량이 늘면 상용 타일 제공자로 바꾼다(URL 한 줄).

## 검토했지만 보류한 것: 네이티브 백그라운드 지오펜싱

도착 알림을 정말 앱이 닫혀 있을 때 띄우려면 네이티브 지오펜싱이 필요하다. 이번에는 구현하지 않았다. 이 저장소에서 빌드·테스트할 수 없는 Swift/Kotlin 코드가 들어가야 하고, 스토어 심사 부담이 커지기 때문이다. 하려면 다음 작업이 필요하다.

- **플러그인:** Capacitor 공식 플러그인에는 지오펜싱이 없다(`@capacitor/geolocation`은 포그라운드 위치만 다룬다).
  - `@capacitor-community/background-geolocation`: 지오펜싱이 아니라 상시 추적이다. Android에서 상시 알림이 붙는 포그라운드 서비스가 필요하고 배터리를 많이 쓴다. 목적에 비해 과하다.
  - `@transistorsoft/capacitor-background-geolocation`: 지오펜싱을 지원하지만 Android 릴리스 빌드에 유료 라이선스가 필요하다.
  - 권장안은 작은 **로컬 플러그인**을 직접 만드는 것이다. iOS는 `CLLocationManager.startMonitoring(for: CLCircularRegion)`(앱당 최대 20개, 실효 반경 100 m 이상), Android는 Play services `GeofencingClient` + `BroadcastReceiver`를 쓴다. 기기 재부팅이나 앱 업데이트 뒤에는 다시 등록해야 한다(`RECEIVE_BOOT_COMPLETED`). JS 쪽은 `Platform.geofence?: { set(region | null), permission() }`로 감싼다.
- **동작:** 구역에 들어오면 **로컬 알림만** 띄운다("출두 구역에 도착했습니다 — 출두 체크할까요?"). 알림을 누르면 앱이 열리고, 위의 포그라운드 자동 체크가 실제로 체크한다. 백그라운드에서 직접 체크하려면 네이티브 쪽에 Supabase 세션과 동기화를 다시 구현해야 하므로 하지 않는다.
- **권한:**
  - iOS는 "항상 허용"이 필요하다(`NSLocationAlwaysAndWhenInUseUsageDescription`). 먼저 "사용 중에만"을 받고 나중에 올려 달라고 요청한다.
  - Android 10 이상은 `ACCESS_BACKGROUND_LOCATION`을 따로 요청해야 한다. Android 11 이상에서는 사용자가 설정 화면에서 "항상 허용"을 직접 골라야 한다.
- **스토어 심사:**
  - Google Play는 백그라운드 위치 권한 선언서와 기능 시연 영상, 권한 요청 전 앱 안의 명시적 고지(prominent disclosure)를 요구한다.
  - App Store는 "항상" 권한이 왜 필요한지 심사 노트와 사용 설명에 적어야 한다. 출석 체크만을 위한 백그라운드 위치는 거절될 위험이 있다(5.1.1 데이터 최소화).
- **갱신:** 발의로 구역이 바뀌면, 앱이 새 규정을 받는 순간 등록된 영역을 다시 설정해야 한다. 그 전까지는 옛 구역으로 알림이 온다.
- **테스트:** 시뮬레이터·에뮬레이터의 위치 시뮬레이션으로 진입 이벤트를 수동 확인해야 한다. 이 저장소의 vitest로는 검증할 수 없다.

그 밖의 후속 작업: iOS 웹뷰의 geolocation은 OS 권한 창 외에 웹뷰 권한 창이 한 번 더 뜰 수 있다. 문제가 되면 네이티브 셸의 `GeolocationPort`를 `@capacitor/geolocation`으로 바꾼다. 의존성 추가와 `cap sync`가 필요하다.

## 결과

- (+) 요청의 세 단계 가운데 "구역 안에서만 체크"와 "앱을 열면 자동 체크"를 웹과 네이티브에서 같은 코드로 제공한다.
- (+) 서버 변경도, 위치 이력도 없다. 구역 변경은 기존 규정 거버넌스를 그대로 따른다.
- (−) 앱을 열어야 체크된다. 닫혀 있는 동안의 도착 알림은 없다.
- (−) 위치는 검증되지 않는 자기 신고다. 조작을 막지 못한다.
- (−) 지도 타일과 검색이 외부 서비스(OSM)에 의존한다. 오프라인이면 지도 없이 현재 위치로만 고를 수 있다.
